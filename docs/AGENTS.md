# Mission

We are NOT building a government website.

We are creating a premium digital experience that introduces Desa Karamatwangi through storytelling, beautiful visuals, and modern interaction.

Visitors should feel they are exploring the village, not reading documentation.

---

# Core Design Philosophy

Nature first.

Technology second.

Technology should enhance nature, never overpower it.

The website should feel:

- Calm
- Elegant
- Organic
- Premium
- Warm
- Modern
- Human

Avoid making it look like an AI startup or crypto landing page.

---

Secondary

- Government
- Researchers

Most visitors will use MOBILE devices.

Every UI decision must prioritize mobile.

# Typography

Headings

Plus Jakarta Sans

Body

Inter

Hierarchy must always be clear.

---

# Layout Principles

Use generous spacing.

Avoid clutter.

One clear focal point per section.

Every section must have breathing room.

Do not overcrowd layouts.

---

# Mobile First

Every component must be designed for mobile first.

Touch targets must be at least 44px.

Avoid hover-only interactions.

Avoid horizontal scrolling.

Prioritize thumb-friendly layouts.

Animations must remain smooth on mid-range Android devices.

---

# Motion

Motion should feel natural.

Allowed

Fade

Scale

Blur

Slide

Parallax

Slow background movement

Not allowed

Flashy animations

Fast transitions

Aggressive bouncing

Constant floating effects

Motion should guide attention.

Never distract users.

---

# Images

Images are the main storytelling medium.

Prefer:

Real photography

Drone shots

Local people

UMKM

Nature

Agriculture

Culture

Avoid generic stock images.

Images should feel authentic.

---

# Cards

Cards should be clean.

Rounded corners.

Thin borders.

Minimal shadows.

Readable typography.

Good spacing.

---

# Buttons

Buttons should feel modern.

Rounded.

Simple.

Clear.

One primary CTA per section.

Avoid excessive button styles.

---

# Accessibility

Semantic HTML.

Keyboard navigation.

Visible focus states.

Good color contrast.

Readable typography.

Respect prefers-reduced-motion.

Accessibility is mandatory.

---

# Performance

Performance is a feature.

Avoid unnecessary JavaScript.

Avoid heavy animations.

Lazy load media.

Optimize images.

Do not sacrifice performance for visual effects.

---

# Coding Rules

Prefer existing components.

Avoid duplicate components.

Do not rewrite working code.

Modify only what is necessary.

Reuse design tokens.

Keep code readable.

---

# Component Philosophy

Every component should have one responsibility.

Avoid giant components.

Prefer composition.

Do not duplicate logic.

---

# Design Consistency

Before creating a new component ask:

Can an existing component be reused?

Can this design follow existing tokens?

Can spacing remain consistent?

Can this be simpler?

If yes,

choose the simpler solution.

---

# UX Principle

Users should never feel lost.

Navigation should always be obvious.

Content should be easy to scan.

Scrolling should feel like progressing through a story.

---

# Storytelling

The homepage is not a dashboard.

It is an experience.

The scroll journey should feel like:

Welcome

↓

Discover

↓

Explore

↓

Experience

↓

Connect

Every section must naturally lead to the next.

---

# Decision Rule

Whenever there are multiple solutions:

Choose the one that

- is simpler
- is faster
- is easier to maintain
- improves mobile UX
- preserves consistency

Never choose complexity for the sake of aesthetics.

---

# AI Instructions

Before editing code:

Understand the existing implementation.

Respect current architecture.

Avoid unnecessary refactoring.

Only modify files related to the requested task.

Never redesign unrelated pages.

Preserve functionality.

Improve quality incrementally.

## Component Philosophy

Before creating a new card component, ask:

Can this information be communicated through storytelling instead?

Prefer editorial layouts over dashboard grids whenever possible.

Use cards only when comparison or scanning is the primary user task.
